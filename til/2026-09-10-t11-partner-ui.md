# TIL — T11 거래처 관리 UI: 슬라이드오버 드로어 + 단가표 편집

## 1. 백엔드 재사용, renderer만 추가 (무수정 원칙)

- T4 `partnerService` + T8 IPC 브릿지(`sme.partners.*`)가 완비되어 있어
  `main.js`/`preload.js`/`src/main/**`는 손대지 않았다.
  변경은 `renderer/` 3건(신규 뷰·nav 탭·스크립트 로드) + 단위 테스트 1건のみ.
- 프론트가 호출한 채널 4종: `partners.list`(검색 LIKE) /
  `partners.get`(상세 리프레시용) / `partners.save`(INSERT 자동채번·UPDATE) /
  `partners.delete`(삭제 확인 모달 뒤 실행). 전부 `App.call` 단일 경유 —
  `window.api` 직접 참조 0건이 R1 게이트의 핵심 전제다.

## 2. 슬라이드오버 드로어: translateX + rAF 2프레임

- `App.modal` 중앙 모달 대신 우측 고정 패널을 선택: 목록을 가리지 않고
  행 클릭 → 즉시 편집이라는 화면② 동선에 맞고, 테이블 컨텍스트가 유지된다.
- 구현: 오버레이(`fixed inset-0`, `justify-content:flex-end`) + 패널
  (`width:min(480px,92vw)`, 초기 `translateX(100%)`)를 `appendChild` 후
  `requestAnimationFrame` 2중 호출로 `translateX(0)` 전이(200ms ease).
  닫기는 역전이 후 180ms 뒤 `remove()`. 별도 CSS 파일 수정 없이
  인라인 스타일로 완결 — design-system 클래스(`sme-field/sme-btn/sme-error` 등)는 그대로 재사용.
- 삭제는 드로어 안에서 `App.modal` 확인 다이얼로그를 한 번 더 띄우는
  2단계 구조(드로어=편집, 모달=파괴적 확인)로 역할 분리.

## 3. 사업자번호 마스킹/검증: 표시는 관대, 저장은 엄격

- 입력 중에는 숫자만 추출해 `000-00-00000` 형태로 점진 마스킹
  (온보딩 `maskBizNo`와 동일 로직 재사용), 저장 시에는 정규식
  `/^\d{3}-\d{2}-\d{5}$/` 엄격 검증 + 인라인 에러.
- 백엔드는 `bizNo`를 nullable로 받지만 화면② 스펙상 필수로 강제 —
  프론트 검증이 서버 제약을 강화하는 방향이라 불일치 리스크 없음.
  서버의 중복 `bizNo` 검증·`partnerName` 필수는 에러 메시지를
  그대로 `#pt-error`에 노출해 중복 구현을 피했다.

## 4. 품목단가표 배열 검증: 빈 행 스킵 + 행 단위 진단

- 서버 `normalizePriceTable` 규칙(품목명 필수·`unitPrice` 0 이상 정수)을
  프론트 `collect()`에 미러링: 이름·단가 모두 빈 행은 스킵,
  한쪽만 있으면 `${i+1}번째 항목` 지목 에러.
- 단가 입력은 `[^0-9]` 제거 후 `Number` 변환 — 서버의 `typeof number` 체크와
  맞물리도록 전송 전 정수화. 빈 단가표도 허용(청구 배치에서 제외되는
  서버 동작과 일치)하므로 `[]` 저장이 정상 플로우다.

## 5. R1 게이트 통과 배경

- `partnersView.test.js` 8건이 뷰 등록·채널 3종(list/save/delete)·
  키 필드 7종·디바운스 250·`translateX`·`node --check`·금지패턴 0건을 고정.
  Red(파일 없음) → Green(8/8) TDD로 진행했다.
- 금지패턴 스캔 시 주의점: 숫자 리터럴 `'1234'`·`'B1'`이 플레이스홀더에도
  들어가면 안 되므로 예시값은 `000-00-00000`·`054-000-0000` 계열만 사용.
  `window.api.sme` 직접 호출 대신 `App.call`을 쓰면
  `window.api.(?!sme)` 검사와 `window.api.sme.*` 존재 검사를 동시에 만족한다.
