# 10인 이하 소규모 제조업체용 오픈소스 ERP (SME-ERP)
## 사용자 'Aha Moment(아하 모먼트)' 정의 및 제품 기획 전략

> **문서 버전**: v1.0  
> **작성 주체**: `myapp-planner` (기획/설계)  
> **대상 사용자**: 10인 이하 소규모 제조기업(정밀가공, 금속/사출, 부품조립 등) 대표자 및 겸직 실무자 (사장, 배우자, 총무 겸임 1인)  
> **현실 페르소나**: 현장 가공 업무와 납품을 직접 뛰면서, 밤이나 월말에 엑셀과 통장 내역서를 대조하며 청구서와 세금계산서를 끊는 50~60대 대표님 또는 실무자.

## 1. 10인 이하 제조업체 실무자가 엑셀을 버리게 만드는 결정적인 'Aha Moment'

### 1.1 현장의 진짜 고통 (Pain Point)
10인 이하 제조업체의 ERP 도입 실패율은 90%에 달합니다. SAP, 더존, 이카운트 같은 ERP는 기능이 너무 많고 입력할 항목(공정코드, BOM, 창고위치, 회계계정과목 등)이 과도하여 결국 **"그냥 엑셀이 제일 편하다"**로 회귀합니다.
반면 엑셀을 쓰면서 겪는 치명적인 문제는 딱 세 가지입니다:
1. **"말일 청구서 지옥"**: 매달 말일마다 거래처 30~40곳의 지난달 단가를 엑셀에서 일일이 찾아 복사하고, 부가세를 계산해 PDF로 인쇄/발송하는 데 주말 반나절이 통째로 날아감.
2. **"입금 쪼개기/미수금 추적 불가"**: 거래처가 1,000만원 청구에 730만원만 쪼개서 입금하면, 엑셀에서는 '어느 건이 미납이고 현재 총 얼마가 남았는지' 수식이 꼬여 거래처와 잔액 시비 발생.
3. **"복잡한 솔루션의 진입장벽"**: 비싼 월 구독료, 어려운 용어, 인터넷 연결 끊김 걱정, 백업 불안.

### 1.2 결정적인 단 하나의 'Aha Moment'
> **"매달 말일 4시간 걸리던 40개 거래처 청구서 작업이 '단 1번의 클릭'으로 5초 만에 끝나고, 거래처 원장 잔액이 통장 입금액과 1원 단위까지 실시간으로 딱 맞아떨어지는 순간!"**

- 사용자가 느끼는 감정: *"어? 내가 일일이 거래처 찾아서 복사 안 해도 지난달 단가 그대로 청구서 40장이 다 만들어졌네? 게다가 300만원 입금 찍으니까 미수금이 자동으로 딱 깎여서 원장으로 바로 출력되네? 엑셀보다 100배 편한데 돈도 안 드네!"*
- 즉, **'회계/물류의 완벽성'이 아니라 '월말 청구·입금정산 시간의 극적인 단축(4시간 → 5분)'**이 사용자를 붙잡는 핵심 계기입니다.

## 2. 감탄을 이끌어낼 3대 킬러 인터랙션/기능 (Killer Moments)

설치부터 첫 청구서 발행, 첫 입금까지의 사용자 여정(User Journey)에서 3번의 연속된 'Aha'를 설계합니다.

```
[여정 1: 설치 1분] ──> [여정 2: 월말 5초] ──> [여정 3: 입금 즉시]
 (3단계 온보딩)      (원클릭 일괄 청구)     (원장 실시간 차인지급)
      ↓                     ↓                      ↓
 "어? 세팅 끝?"      "청구가 벌써 끝?"       "미수금이 저절로 계산?"
```

---

### 킬러 인터랙션 ① : [온보딩] "빈 화면 없는 60초 마법사" + 샘플 제조업 템플릿 즉시 주입
- **사용자 경험**:
  - 대부분의 ERP는 설치 후 빈 테이블만 덩그러니 나와 사용자가 질려버립니다.
  - SME-ERP는 실행 즉시 깔끔한 3단계 마법사 카드가 뜨며, **사업자번호와 회사명만 입력**하면 끝납니다.
  - 특히 Step 3에서 **"[소규모 가공/제조업 표준 단가표 적용]"** 체크박스를 제공하여, 클릭 한 번으로 기본 거래처 3곳(예: 대양공업, 한일금속 등)과 대표 품목(정밀가공, 밀링가공, 레이저절단)이 즉각 세팅됩니다.
- **감탄 포인트**:
  - *"설치하자마자 우리 공장에 맞는 거래처와 단가표가 이미 예쁘게 채워져 있어서, 매뉴얼을 1페이지도 안 읽고도 뭘 해야 할지 직관적으로 알겠다!"*

---

### 킬러 인터랙션 ② : [청구] "월 일괄 청구서 원클릭 생성" (5초의 기적)
- **사용자 경험**:
  - 매월 25일~말일, 상단 배너에 강조된 파란색 **[2026년 9월 정기 청구서 일괄 생성]** 버튼 하나만 누르면 팝업이 뜹니다.
  - "등록된 활성 거래처 38개사 / 총 공급가액 ₩35,200,000 / 부가세 ₩3,520,000"이 자동으로 프리뷰되고, **[일괄 발행 확정]**을 누르는 순간 38건의 청구서가 일괄 생성되며 각각의 거래처 원장에 `매출청구`로 동시 기표됩니다.
  - 여기에 제조업 실무자가 가장 좋아하는 **[선택 거래처 청구서 PDF 일괄 인쇄 / 이메일 발송]** 기능이 연동됩니다.
- **감탄 포인트**:
  - *"지난달 엑셀 양식 열어서 업체명 바꾸고 날짜 바꾸고 금액 계산기 두드리던 짓을 이제 영원히 안 해도 된다!"*

---

### 킬러 인터랙션 ③ : [입금/원장] 통장 입금액 '부분 입금' 자동 배분 & 실시간 차인지급잔액
- **사용자 경험**:
  - 제조업 현장은 거래처가 청구액 딱 맞게 주는 경우가 드뭅니다. (예: 450만원 청구에 300만원만 입금).
  - 화면 ④(입금/원장)에서 거래처를 누르고, 우측 빠른 입금 카드에 **[오늘 날짜] [3,000,000원] [입금 반영]**을 누르면:
    1. 하단 타임라인 원장에 녹색 입금 행이 즉시 착 달라붙음.
    2. 오래된 청구서부터 자동으로 300만원이 채워지며 상태가 `부분입금 (잔여 150만원)`으로 즉시 변경.
    3. 우측 상단과 거래처 목록의 **'현재 미수금 잔액'**이 4,500,000원 → 1,500,000원으로 부드러운 애니메이션과 함께 즉각 갱신.
    4. **[원장 인쇄(A4)]** 버튼을 누르면 거래처에 팩스/카톡으로 보낼 수 있는 공문 스타일의 '거래처별 거래 원장'이 완벽하게 출력됨.
- **감탄 포인트**:
  - *"거래처 사장님이 '우리 미수금 얼마 남았소?' 전화 올 때마다 엑셀 뒤지느라 진땀 뺐는데, 이제 화면 열자마자 1초 만에 150만원 딱 찍어서 원장 카톡으로 쏴줄 수 있다!"*

## 3. 이를 제품 기획 및 설계에 녹여내는 구체적 방안

이 세 가지 'Aha Moment'가 실제로 작동하기 위해, 앞서 수립한 WBS 및 기능 설계에 다음과 같은 기획 장치들을 명시적으로 반영합니다.

### 3.1 UI/UX 레벨의 기획적 장치
1. **첫 실행 빈 화면(Empty State) 제로화**:
   - T3/T9 온보딩 구현 시, 온보딩 완료와 동시에 "샘플 거래처 2~3건"이 선택적으로 들어가게 하여 대시보드의 아름다운 그래프와 숫자들을 사용자가 첫날 바로 목격하게 함.
2. **복잡한 설정 숨김 (Zero-Config principle)**:
   - 복식부기 차변/대변, 계정과목, 마감전표 분개 등의 용어를 UI에서 철저히 배제.
   - 오직 **'청구(매출)'**, **'입금(받은 돈)'**, **'미수금(남은 돈)'** 3개 단어만 사용하여 인지 부하를 0으로 낮춤.
3. **숫자의 시각적 보상 (Visual Satisfaction)**:
   - 청구서 발행이나 입금 처리 시 숫자가 즉시 반응하는 카운팅 트랜지션 및 완납 시 산뜻한 녹색 배지(`완납`) 제공.
   - 인쇄 미리보기는 대한민국 세무/상거래 표준 양식(공급받는자 보관용 파란색/빨간색 라인)을 철저히 준수하여 신뢰감 부여.

### 3.2 백엔드 & 데이터 레벨의 뒷받침 (WBS 연계)
1. **FIFO(선입선출) 입금 자동 충당 로직 (`T6 ledgerService`)**:
   - 부분 입금 시 사용자가 어느 청구서에 얼마씩 배분할지 고민할 필요 없이, 시스템이 미수 청구서의 발행일 순으로 자동 충당해주는 알고리즘 탑재.
2. **트랜잭션 기반 일괄 생성 (`T5 invoiceService`)**:
   - 100개 거래처 청구서 생성도 SQLite WAL 트랜잭션(`BEGIN IMMEDIATE`)으로 0.1초 안에 완료되어 "렉 없이 즉시 끝나는 쾌감" 전달.
3. **한국 세무 표준 절사 (`Math.trunc(amt * 0.1)`)**:
   - 1원의 오차도 허용하지 않는 단가/부가세 계산을 보장하여 엑셀과의 대조 검증에서 100% 신뢰 확보.

## 4. 요약 결론: SME-ERP의 핵심 가치 제안

| 비교 항목 | 기존 엑셀 작업 | 기존 상용 대기업 ERP | **SME-ERP (오픈소스)** |
|---|---|---|---|
| **월말 청구 소요시간** | 3~4시간 (수기 복사, 계산) | 1시간 (복잡한 메뉴 이동) | **5초 (원클릭 일괄 생성)** |
| **미수금 잔액 확인** | 수식 오류 빈번, 10분 이상 소요 | 계정별 원장 조회 필요 (어려움) | **1초 (대시보드 & 실시간 원장)** |
| **비용 및 데이터 소유권** | 무료이나 파일 분실 위험 | 매월 유료 구독료 (계정당 과금) | **완전 무료 오픈소스 + 내 PC 로컬 DB** |
| **학습 곡선** | 익숙하나 자동화 한계 | 교육/매뉴얼 필수 (수주일 소요) | **온보딩 1분으로 즉시 실무 투입** |

**"1분 설치, 5초 청구, 실시간 미수금 원장"** — 이 세 가지가 10인 이하 제조업체 실무자가 SME-ERP를 한 번 켜보고 다시는 엑셀로 돌아가지 못하게 만드는 가장 강력한 **Aha Moment**입니다.

## 5. Aha Moment 평가 기반 고도화 (v1.1) — T09~T11

10인 이하 제조업 Aha Moment 평가에서 3대 핵심 과제를 도출했습니다. (문서 상단 버전 표기는 유지하며, 본 섹션은 **v1.1** 기준입니다.)

### 5.1 과제1 [최대 병목] — 엑셀 복붙 3초 가져오기 (Magic Import, T09)

- **기능 요약**: 온보딩 직후 실제 거래처 등록 마찰(수작업 타이핑으로 인한 약 60% 이탈)이 최대 병목으로 확인되어, 엑셀 표를 그대로 붙여넣어 한 번에 거래처를 등록하는 **Magic Import**를 도입했습니다.
- **데이터 흐름**: 클립보드 TSV/CSV → `parsePartnersText(text)` 행 분해 → 미리보기 모달 → `savePartnersBulk(companyId, rows)` → `{created, skipped, errors}`
- **엣지 케이스**:
  - 빈 클립보드 → 빈 결과 반환(오류 아님)
  - 헤더 유무(첫 행에 상호/거래처/사업자 키워드가 있으면 헤더로 감지, 없으면 위치 기반 파싱)
  - 컬럼 부족 → 행별 error로 수집(전체 중단 금지)
  - 중복 `bizNo` → skip(upsert 아님)
  - 동일 거래처 복수행 → 단가 그룹핑
- **구현 파일**: `src/main/services/bulkImportService.js`, `src/main/services/partnerService.js`(`savePartnersBulk`), `src/main/ipc/smeHandlers.js`(`sme:partners:parseBulk`, `sme:partners:saveBulk`), `preload.js`, `renderer/js/views/partners.js`
- **상태**: 구현 완료 · 테스트 PASS

### 5.2 과제2 [도파민 보상] — 월 일괄 청구서 생성 완료 축하 모달 (T10)

- **기능 요약**: 월 일괄 청구서 생성이 끝나는 순간, 실제 발행 장수와 절약 시간을 되돌려주는 축하(도파민 보상) 모달을 띄웁니다.
- **데이터 흐름**: 청구 `createBatch` summary → `estimateSavingTime(count × 5.5분, 5분 단위 반올림)` → `App.modal`(실제 장수·절약시간)
- **엣지 케이스**:
  - 0건이면 모달 생략
  - `skippedCount > 0`이면 '제외 N건' 병기
  - 장수 하드코딩 금지(`summary.totalCount` 사용)
- **문구 예**: `🎉 청구서 38장 발행 완료! 엑셀 야근 3시간 30분을 절약하셨습니다`
- **구현 파일**: `renderer/js/views/invoices.js`, `tests/unit/calc/savingTime.test.js`
- **상태**: 구현 완료 · 테스트 PASS

### 5.3 과제3 [리텐션/공유] — 원장 '거래처 카톡 전송용 이미지 복사' (T11)

- **기능 요약**: 원장 화면에서 거래처에 카톡으로 바로 보낼 수 있는 요약 이미지를 클립보드에 복사합니다.
- **데이터 흐름**: ledger view → 지정 6필드(상호명/대표자/거래일자/공급가액/입금액/차인지급잔액) 추출 → canvas 2D 렌더 → `toDataURL(png)` → `sme:clipboard:copyImage` → `clipboard.writeImage(nativeImage)`
- **엣지 케이스**:
  - 외부 lib 0(수동 layout)
  - 빈 원장이면 버튼 비활성
  - dataUrl `data:image/png;base64,` allowlist(비PNG/스킴/HTML 거부)
  - clipboard 실패 시 토스트
- **구현 파일**: `renderer/js/views/ledger.js`, `main.js`, `preload.js`, `tests/unit/renderer/clipboardImage.test.js`
- **상태**: 구현 완료 · 테스트 PASS

### 5.4 확정 결정

- 파싱은 메인 순수함수로 구현(단위 테스트 가능).
- 기본 컬럼 순서: 거래처명 / 사업자번호 / 대표자 / 연락처 / 품목명 / 단가.
